# Strategy & Monetization

## When to use
When evaluating how HackHub's positioning, feature gating, or value narrative connects to business outcomes — pricing pages, plan differentiation copy, upgrade prompts, or feature-level value communication.

## Patterns

**Anchor value before showing price**
If HackHub introduces paid tiers, the upgrade prompt copy must establish concrete value before naming a price or plan. "Unlock advanced voting criteria, custom judging rubrics, and export tools" is more persuasive than "Upgrade to Pro" without context.

**Feature-level positioning**
High-value features like `VotingCriteriaManager.tsx` and `TeamVideoCall.tsx` should have copy that explains the job they do, not just the capability. "Set custom scoring rubrics per judging panel" speaks to a manager's workflow; "Flexible voting criteria" does not.

**Differentiate by ICP, not by feature count**
Manager-tier messaging should emphasize control and oversight. Participant-tier messaging should emphasize access and collaboration. Mixing these in a single pricing or upgrade page creates confusion about who the product is actually for.

## Pitfall
Don't write monetization copy before the value narrative is clear. If the free-tier experience doesn't demonstrate enough value for users to see what they'd be paying to extend, upgrade prompts will feel arbitrary. Fix the core value communication first.
